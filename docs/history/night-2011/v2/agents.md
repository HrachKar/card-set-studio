# Два агента: составитель и отборщик (проект, на утверждение)

Оба работают текстом и внутри Claude Code, то есть входят в подписку гейм-дизайнера. Платный API нужен только для картинок.

## Где они живут

| Шаг | Кто выполняет | Стоимость | Результат |
|---|---|---|---|
| 1. Составитель | сам Claude Code в скилле (основной разговор) | $0 сверх подписки | `candidates.md`: 25–30 кандидатов |
| 2. Отборщик | отдельный субагент Claude Code (новый контекст, видит только кандидатов и правила) | $0 сверх подписки | `compose/sets.json`: 3 варианта по 10 |
| 3. Проверка кодом | `python3 -m studio new --sets ... --stop-after dry` | $0 | `review_sets.md`, `review_prompts.md`, ошибки сплита и цветов |
| 4. Картинки | `python3 -m studio new --sets ...` | ~$4–9 за 30 карточек | листы и отчёт |

Почему отборщик — отдельный субагент: если отбирает тот же разговор, который придумывал, он защищает свои идеи. Новый контекст смотрит на список как сторонний редактор.

API-составитель (`studio/compose.py`, GPT-5.5) остаётся запасным вариантом для запуска без Claude Code, например из скрипта.

Шаг 2 платный только в одном случае: если скилл запускают через API, а не по подписке. Через Claude Code это бесплатно.

## Промпт составителя (шаг 1)

```
Жанр: <жанр>. Пожелания: <пожелания>.
Прочитай studio/rules.md. Выбери ОДНУ подтему жанра — знаковое место или занятие, которое есть почти в каждом фильме жанра.
Напиши 25–30 кандидатов этой подтемы таблицей:
| # | Объект (англ., 1–2 слова) | Что нарисовать (одно предложение: форма, цвет, материал) | Класс | Кат. 1–4 | Носимый? | Почему игрок узнает |
Классы: building/place, vehicle, creature, food/drink, artifact, household, nature, symbol, costume.
Минимум 2 кандидата в каждом классе, кроме creature (если животные запрещены).
Запрещено: гибриды (знак темы на случайной вещи), оружие, люди, текст, предметы конкретных франшиз из стоп-листа.
```

## Промпт отборщика (шаг 2, субагент)

```
Ты главный геймдизайнер. Тебе дали правила (studio/rules.md) и список кандидатов. Ты их не придумывал.
1. Вычеркни кандидатов, которые: не узнаются по силуэту размером с ноготь; гибриды; похожи на конкретную франшизу; сложной конструкции (много тонких деталей, спиц, механизмов).
2. Собери вариант A — лучшие 10: квоты классов (≤2 на класс, ≤1 носимый, ≥6 классов, есть еда/напиток, есть постройка или транспорт), категории 3/2/3/2 ±1, разные силуэты и масштабы.
3. Собери B и C из того же списка: другие 10, пересечение с A не больше 4 карточек, те же квоты.
4. Для каждого сильного кандидата, который не попал в A, напиши одной строкой почему.
5. Запиши JSON в формате night-2011/sets/*.json (общая шапка, поля карточек) и проверь: python3 -m studio new --sets <file> --stop-after dry.
```

## Что можно проверять кодом бесплатно (добавить в validate, предложение)

- Квоты классов: не больше 2 на класс, не больше 1 носимого, не меньше 6 классов. Нужны поля `class` и `wearable` в каждой карточке.
- Не больше 2 карточек со словом glowing/neon/chrome в описании.
